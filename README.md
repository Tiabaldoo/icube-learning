# icube-learning

Нужен Node.js 22.12+; рекомендуется Node.js 24.

В игре «Собираем звёзды» 16 шагов в Блоках и 17 в JavaScript.
Число шагов зависит от действий режима, а не от общего шаблона.
Уроки: `lessons/collect-stars-01/lesson.json` и `javascript/lesson.json`.
Урок заканчивается экраном «Игра готова!». Тестов и сохранения прогресса нет.
Улучшения необязательные и относятся к конкретной игре. Для сбора звёзд доступна
«Добавь музыку» в Блоках, JavaScript и Python; для лабиринта улучшений пока нет.

```bash
npm ci
npm run dev
npm run build
```

## Desktop build

Node.js 24 рекомендуется. Версия desktop — `package.json` (`0.1.0`).
Electron закреплён на `44.6.0`. macOS использует внутренние ASCII-имена
`iCubeGames` (executable и Helpers), отображаемое имя — «Айкуб Игры».
Один frontend используется для сайта и встроенной офлайн-копии уроков.

```bash
npm run dev:desktop
npm run build:desktop       # установщик для текущей ОС
npm run build:desktop:mac   # на macOS
npm run build:desktop:win   # на Windows
```

Установщики сохраняются в `release/`, в git не попадают. Подписи и автообновления
не настроены; macOS может предупредить о неизвестном разработчике.
На macOS запускайте только доверенный установщик через «Открыть»/настройки безопасности.

В GitHub: **Actions → Desktop release → Run workflow** — скачать установщики
в artifacts запуска. Для релиза обновите `version` и lockfile, затем создайте
совпадающий тег (`git tag v0.1.0` и `git push origin v0.1.0`). Workflow собирает
Windows x64 и macOS x64/arm64 на отдельных runners и прикладывает установщики
к **Releases**. Обычный push в `main` desktop-сборку не запускает.

## Публикация учебных материалов

1. Добавьте `lessons/<стабильный-id>/game.json`, уроки и ресурсы; зарегистрируйте
   игру и пути уроков в `content/registry.json`. Эта регистрация используется
   и встроенной копией, и генератором пакета. Изменения существующих уроков
   выполняйте в их текущих JSON/ресурсах.
2. Для улучшения добавьте `extras/<id>/` с уроками доступных режимов, метаданные
   в `extras/catalog.json` и его ID в `improvements` нужной игры в реестре.
   Каждый мини-урок начинает работу с готового основного проекта, независимо
   от других улучшений. Не регистрируйте пустые инструкции.
3. Увеличьте `version` в `content/registry.json` (например, `1.0.1`). Формат —
   три целых числа. Выполните `npm run content:prepare`, `npm run content:test`
   и `npm run build`. Генератор проверяет формат, существование используемых
   изображений/кода, совместимость, размер и SHA-256.
4. Закоммитьте исходные материалы, `content/version.json`, новый файл
   `public/content/versions/<версия>/bundle.json` и `public/content/manifest.json`;
   отправьте в `main`. Существующие версии пакетов не меняйте и не удаляйте.
   Генератор отказывается перезаписывать пакет другим содержимым под прежней версией.
5. Обычный Pages workflow публикует единый согласованный artifact (файлы пакета
   готовы до записи манифеста). Desktop release не запускается, установщик не нужен.

Стабильный адрес: https://tiabaldoo.github.io/icube-learning/content/manifest.json.
Манифест ссылается на неизменяемый JSON-пакет соответствующей версии. Пакет содержит
уроки, текстовые образцы MakeCode и PNG как данные; HTML/скрипты не исполняются.
Веб-версия получает этот пакет через обычный fetch с учётом Vite base path.

Electron открывает встроенные уроки сразу, проверяет обновления в фоне и предлагает
«Обновить». Ручная команда — «Проверить обновления». Сеть имеет таймаут и лимит размера.
Renderer не получает Node.js или доступ к файловой системе. Main process сохраняет
пакет в `userData/learning-content`, проверяет SHA-256, размер, формат, пути и минимальную
версию приложения, затем атомарно переключает указатель. Предыдущий пакет сохраняется;
повреждённый активный пакет при запуске заменяется предыдущим или встроенным.
Новый пакет меняет каталог после возврата в него; данные открытого урока остаются прежними.
Прогресс ребёнка не хранится. Версия приложения и версия материалов независимы.

Для следующего этапа нужны независимые инструкции и реальные ресурсы для «Звук звезды»,
«Игра на время», «Добавь врага» и улучшений лабиринта. Эти карточки пока не отображаются.

Для снимков обновлённого урока (11 схем блоков и 9 реальных UI-скриншотов)
нужен доступ к интернету:

```bash
npx playwright install chromium
npm run capture:lesson
# Можно повторить только одну часть:
npm run capture:lesson -- --blocks
npm run capture:lesson -- --ui
# При необходимости можно выбрать конкретные assets:
npm run capture:lesson -- --blocks blocks-12
npm run capture:lesson -- --ui js-choose-star-image
```

Новые снимки сохраняются в `images/blocks/` и `images/ui/`.
При подготовке UI-снимков компилируются только необходимые образцы MakeCode.
Скрипт использует внутренний API MakeCode; изменения сайта могут потребовать
обновления скрипта. При ошибке команда завершается с ненулевым кодом.

Прежняя команда `npm run capture:blocks -- lessons/collect-stars-01` сохранена
для исходных шести файлов `steps/step*.ts`: её PNG остаются в `images/`.
Ей также можно передать папку `steps/` или один файл `steps/step03.ts`.

`actionType` описывает действие, `visual.type` выбирает схему блоков,
скриншот интерфейса или code viewer. У `modify-code` есть `change.before/after`
и `changedLines`; новые строки задаются в `newLines`.
Образцы программ находятся в `steps/blocks-micro/` и `steps/javascript-micro/`.
Код рисунков ребёнок не переписывает: вводит img с двумя обратными кавычками, открывает палитру
и выбирает изображение в галерее MakeCode.
