# Стандарт учебных материалов «Айкуб Игры»

Уроки рассчитаны на детей от 8 лет. Один шаг — одно законченное действие, а не один щелчок. Используем существующие поля: «Где найти», инструкции «Что сделать», «Проверь» и скрытое объяснение «Почему это работает?».

До 3★ включительно подробно объясняем и повторяющиеся действия: категория, название команды, выбор параметров, место вставки, результат. На 4–5★ можно сокращать только знакомые простые действия. Новые темы и составные команды всегда объясняем полностью.

Составной блок показываем в процессе сборки: основная команда, источник овальной переменной или условия, подходящее место внутри команды, выбор значений, готовый результат. Используем `visual.images` для полезных последовательностей внутри одного шага. Реальные снимки MakeCode получаем существующим capture-процессом; не рисуем интерфейс. Повторно используем подходящие изображения. `focus` в процентах выделяет конкретные элементы без изменения PNG. Полную карту для сверки можно оставить без маски.

В JavaScript и Python сохраняем просмотр полного кода и подсветку добавленных и изменённых строк. Объясняем точное место вставки, имена, знаки и отступы. Не просим переписывать готовую программу. Для карт, мелодий и пиксельных рисунков используем редакторы MakeCode вместо ручного ввода длинных ресурсов.

Инструкция отвечает «Как сделать?». Теория отвечает «Зачем и как это работает?»: короткие предложения, одно понятие за раз, термины с объяснением, пример из данной игры, порядок действий и последствия другого значения. Для новой сложной темы нужны содержательные небольшие абзацы, обычно 5–8 предложений. Не заменяем объяснение повтором названия команды и не увеличиваем объём одинаковыми фразами.

Переменные, типы и команды появляются после объяснения их создания. Промежуточный код и снимок соответствуют текущему состоянию. Уже созданные команды сохраняются, если инструкция явно не просит их изменить. Последнее состояние совпадает с финальным образцом. «Лабиринт: продолжение» начинается с конца «Лабиринта».

Каждое улучшение начинается с готовой основной игры и не требует другого улучшения. Для него действуют те же правила текста, сборки, изображений и подсветки. Игровую механику, карты и финальные образцы не меняем при методических исправлениях.

Проверяем JSON, ссылки, координаты, последовательность и неизменность финальных образцов целевыми проверками. Выпускаем новый неизменяемый пакет с SHA-256 и подходящей минимальной версией приложения. Старые пакеты не переписываем. Сборку и проверки контента выполняем после завершения изменений. Браузер нужен только для отсутствующих подлинных снимков MakeCode, не для проверки платформы.
