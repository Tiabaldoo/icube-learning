# Лабиринт: продолжение (`maze-02`)

Урок дополняет сохранённый проект `maze-01`. Начальные образцы трёх режимов совпадают с окончанием первого урока; исходная карта `level1` сохранена. В Python следующий шаг меняет только переменную `player` на `my_player`, сохраняя `SpriteKind.player`: это устраняет конфликт со служебным именем MakeCode.

## Карты и механика

`assets/level1.ts` и `assets/level2.ts` — технические образцы карт для компиляции и capture, не задание на ввод hex. Ребёнок создаёт отдельный ресурс `level2` через «Ресурсы → + → Тайловая карта» и рисует его по настоящим снимкам редактора. `assets/map-layout.json` описывает этот же образец для проверки связности. Координаты в инструкциях считаются от 1; программная логика использует плитки-маркеры.

- `collectibleInsignia`: старт; `floorLight3`: враг; `chestClosed`: финиш — как в первом уроке.
- `floorLight2`: место ключа. По одному экземпляру каждого маркера.
- `doorClosedNorth`: единственная дверь в обязательном проходе. Дверь и каменные стены отмечены стенами; остальные маркеры проходимы.
- Один прежний герой, скелет и финиш переиспользуются на обоих уровнях. Один новый ключ скрыт и является призраком на первом уровне.
- Первый финиш вызывает загрузку второго уровня. Только второй завершает игру победой.
- Подбор ключа устанавливает состояние и скрывает ключ. `scene.onHitWall` открывает дверь только при контакте с ней, при наличии ключа: убирает стену и кладёт обычный пол.
- Столкновение со скелетом вызывает восстановление попытки. На втором уровне оно возвращает героя на его старт, восстанавливает тот же ключ, закрывает дверь и вновь включает стену; номер уровня сохраняется.
- `maze-chase` меняет только патрулирование на `follow(..., 45)` с выключенным отскоком. Стены остаются препятствиями; стандартное преследование не строит маршрут вокруг них.

## Подготовка и проверки

Новые PNG сняты в русском MakeCode Arcade существующим Blockly/capture-процессом и в настоящем редакторе Tilemap. Исходный финальный снимок первого лабиринта переиспользован. Карта на снимках соответствует `assets/level2.ts`; картинки не рисовались вместо редактора.

Финальный TypeScript основного урока и преследования проверен `E.compiler.compileAsync({native:false})`, затем преобразован в Blockly без нераспознанных JavaScript-блоков. Финальный MakeCode Python обоих уроков проверен тем же компилятором непосредственно из `main.py`: success, без диагностик.

Минимальная техническая проверка исполняла итоговый TypeScript с подставленными API: переход 1 → 2, подбор без немедленного открытия, касание двери с/без ключа, восстановление после врага пять раз, отсутствие новых спрайтов и финальная победа. Проверка связности карты подтверждает доступность ключа при закрытой двери, недоступность финиша и его доступность после открытия. Это проверка обработчиков и структуры карты; физический игровой сеанс в симуляторе не проводился.

Проверяются JSON, ссылки на новые ресурсы, диапазоны подсветки, пакет SHA-256 существующим валидатором, неизменность предыдущих пакетов и `npm run build`. Интерфейс платформы, Electron и установщики не запускаются.
